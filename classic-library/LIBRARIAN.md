# LIBRARIAN.md — 도서관 사서 작업 지시서

이 문서는 Cowork 예약 작업이 실행될 때마다 Claude가 따라야 하는 표준 절차다.
사용자의 개입 없이 이 지시서만으로 한 배치를 완결할 것.

## 실행 절차 (매 배치)

1. `BOOKLIST.md`를 열어 상태가 `대기`인 책 중 위에서부터 **10권**을 선택한다.
2. 각 책의 카드를 `books/` 폴더에 작성한다. 형식은 기존 카드(`books/analects.md`)와 동일하게:
   frontmatter(title, author, era, category, tags, reliability, slug) → 한 줄 정의 → 개요 → 핵심 인사이트 5~6개(각각 *활용 각도* 포함) → 기획·강연 활용 포인트(주의점 포함) → 대표 개념·프레임워크 → 연결 독서.
   분량은 카드당 500~900단어.
   **category는 반드시 아래 9개 표준 분류 중 하나만 사용하고, 세부 분야명(예: 스토아철학, 우화, 신화, 서사시)은 tags에 넣는다.**
3. `SKILL.md`의 "완성된 카드" 인덱스 표에 새 책 행을 추가한다.
4. `BOOKLIST.md`에서 해당 책들의 상태를 `완료`로, 완료일을 기입한다.
5. `reports/` 폴더에 검증 리포트를 작성한다 (아래 형식).
6. `feedback.md`에 사용자가 남긴 코멘트가 있으면 **카드 작성 전에** 먼저 반영하고, 반영 내역을 리포트에 기록한 뒤 해당 코멘트에 `[반영완료]`를 표시한다.
7. 배치 완료 후 `python fetch_covers.py` 실행 후 `python build_library.py`를 실행해 `library.html`을 갱신한다. python 실행이 불가능한 환경이면, `build_library.py`의 로직(프론트매터 파싱 → 마크다운→HTML 변환 → 표지 팔레트 배정 → 단일 HTML 파일 생성)을 그대로 따라 `library.html`을 직접 재생성한다. 어느 방식이든 새로 작성/수정된 카드가 전부 반영됐는지 확인한다.

## 대기열 보충 규칙

배치 시작 시(위 "실행 절차" 1단계를 실행하기 전에) `BOOKLIST.md`의 상태가 `대기`인 항목 수를 센다.

1. **대기 항목이 20권 미만인 경우**
   - 이번 배치는 평소대로 정상 진행한다 (대기열에서 10권을 골라 카드 작성).
   - 이와 별도로 `CANDIDATES.md` 파일에 분야 균형(동양사상·서양철학·역사·문학·과학·정치경제 등 특정 분야 쏠림 방지)을 맞춘 새 후보 30권을 제안한다. 각 후보는 한 줄 소개와 함께 목록에 올린다. 이미 `CANDIDATES.md`에 있는 미승인 후보와 중복되지 않게 한다.
   - 이번 배치의 검증 리포트 최상단(제목 바로 아래)에 `📋 후보 목록 검토 필요`를 명시한다.
2. **후보의 대기열 반영은 사용자 승인 후에만**
   - `CANDIDATES.md`의 후보는 사용자가 `feedback.md`에 승인 의사를 명시적으로 남기기 전에는 어떤 경우에도 `BOOKLIST.md` 대기열에 추가하지 않는다.
   - `feedback.md`에 승인 코멘트가 있으면, 승인된 책만 골라 `BOOKLIST.md` 대기열(상태 `대기`)에 병합하고, 병합된 항목을 `CANDIDATES.md`에서 삭제한다. 승인되지 않은 나머지 후보는 `CANDIDATES.md`에 그대로 둔다.
3. **대기열도 후보도 없는 경우**
   - `BOOKLIST.md`의 대기 항목이 완전히 0권이고, `CANDIDATES.md`에 사용자가 승인한 후보도 없다면, 이번 배치는 카드를 작성하지 않는다. 대신 검증 리포트에 이 상황(대기열 소진, 승인된 후보 없음)만 사실대로 기록하고 종료한다.

## 분류 규칙 (절대 준수)

`category`는 아래 9개 표준 분류 중 정확히 하나만 사용한다. 새 분류를 임의로 만들지 않는다.

- 철학·사상
- 문학
- 역사·인물
- 정치·사회
- 경제·경영
- 과학·자연
- 전략·리더십
- 자기수양·삶
- 한국고전

- 한국 저자의 고전은 주제와 무관하게 **한국고전**으로 분류한다.
- 기존에 쓰던 세부 분야명(예: 스토아철학, 우화, 신화, 서사시, 희곡, 정치철학)은 category에서 빼고 `tags`에 추가해 검색성을 보존한다.

## 신뢰도 규칙 (절대 준수)

- `원전기반`: 퍼블릭 도메인 고전으로, 원전 내용을 확실히 아는 경우만.
- `요약검증`: 저작권 보호 중인 현대 도서. 반드시 웹 검색으로 2개 이상 출처를 교차 확인한 후 작성하고, 출처를 카드 하단에 명시.
- `미검증`: 교차 확인이 안 된 경우. 가능하면 만들지 말고 리포트에 "보류"로 기록.
- `직접독서`: 사용자가 실제로 읽고 카드에 "## 내 메모"를 남긴 책. 아래 "사용자 메모 처리 규칙" 참조. 배치 작업이 임의로 이 등급을 부여하지 않으며, 사용자의 메모가 실제로 카드에 존재할 때만 적용한다.
- 인용문 날조 금지. 확실하지 않은 문장을 "원문"처럼 쓰지 않는다. 원문 귀속이 불확실하면 "~라는 취지" 또는 "후대의 요약"으로 표기.
- 현대 도서는 원문 장문 인용 금지. 개념·논지 요약만.

## 사용자 메모 처리 규칙 (배치와 무관하게 상시 적용)

사용자가 대화 중 자신이 읽은 책에 대한 감상이나 메모를 언급하면, 배치 실행 여부와 관계없이 즉시 다음을 처리한다.

1. 해당 책의 카드(`books/<slug>.md`)를 찾아 맨 아래에 "## 내 메모" 섹션을 만들고(이미 있으면 이어서), 언급된 날짜(또는 오늘 날짜)와 함께 사용자의 감상·메모를 정리해 추가한다. 해당 책의 카드가 아직 없으면 카드 형식(frontmatter → 한 줄 정의 → 개요 → 핵심 인사이트 → 기획·강연 활용 포인트 → 대표 개념·프레임워크 → 연결 독서)을 갖춰 새로 작성한 뒤 맨 아래에 "## 내 메모"를 추가한다.
2. 사용자가 직접 읽고 "## 내 메모"를 남긴 책은 frontmatter의 `reliability`를 `직접독서`로 승격한다.
3. "## 내 메모" 섹션은 사용자 본인의 기록이므로 **배치 작업이 절대 수정·삭제·요약하지 않는다.** 카드의 다른 섹션(개요, 핵심 인사이트 등)을 배치에서 갱신하더라도 "## 내 메모" 섹션은 그대로 보존한다.

## 자기 플래그 규칙 (사용자 검증 시간 단축의 핵심)

카드 작성 중 확신이 90% 미만인 문장에는 문장 끝에 `⚠️`를 붙인다.
예: 구체적 수치, 일화의 세부, 원문 귀속, 연도.
플래그된 문장은 검증 리포트에 전부 모아서 보여준다.

## 검증 리포트 형식 (`reports/YYYY-MM-DD-batch-NN.md`)

```
# 배치 NN 검증 리포트 (날짜)

## 이번 배치 작성 도서 (10권)
- 책이름 — reliability 등급 — 한 줄 요약

## ⚠️ 확인 필요 항목 (여기만 보시면 됩니다)
- [책이름] 플래그된 문장 원문 + 왜 불확실한지

## 보류/실패
- 작성하지 못한 책과 사유

## 다음 배치 예정 (10권)
- 목록

## 피드백 반영 내역
- feedback.md에서 반영한 사항
```

## 금지 사항

- 한 배치에 10권 초과 작성 금지 (품질 저하 방지).
- 같은 오류가 2회 반복되면(예: 특정 책 자료 확인 실패) 그 책은 보류 처리하고 리포트에 기록. 억지로 진행하지 않는다.
- 기존 완성 카드를 사용자 지시 없이 수정하지 않는다 (feedback.md 반영 제외).
- 배치 작업은 카드의 "## 내 메모" 섹션을 절대 수정·삭제하지 않는다 (위 "사용자 메모 처리 규칙" 참조).

## 사용자의 역할 (참고)

사용자는 배치 완료 후 리포트의 "⚠️ 확인 필요 항목"만 훑어보고,
수정할 것이 있으면 `feedback.md`에 한 줄씩 남긴다. 그게 전부다.
